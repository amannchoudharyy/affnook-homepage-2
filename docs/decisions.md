## Architecture decisions

| #   | Decision                                                                                                             | Reason                                                                                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | Three statically rendered routes: `/` (Operators), `/brands`, `/affiliate-networks`                                  | Each variant is shareable, indexable and fully usable without JavaScript                                                                                                            |
| A2  | Audience switcher implemented as links with `aria-current`                                                           | Works without JavaScript; correct semantics for navigation between pages                                                                                                            |
| A3  | CSS Modules + CSS custom-property tokens; no CSS framework                                                           | Small output, plain CSS, tokens map 1:1 to Figma variables                                                                                                                          |
| A4  | No animation library initially                                                                                       | The prototype's effects are achievable with CSS + IntersectionObserver                                                                                                              |
| A5  | Indexing is opt-in (`SITE_ENV=production` + https `SITE_URL`)                                                        | Staging and previews can never be indexed by accident                                                                                                                               |
| A6  | TypeScript 6.0.x instead of 7.x                                                                                      | typescript-eslint supports TypeScript `<6.1`                                                                                                                                        |
| A7  | ESLint 9.x instead of 10.x                                                                                           | eslint-plugin-jsx-a11y (used by eslint-config-next) does not yet declare ESLint 10 support                                                                                          |
| A8  | SEO titles and descriptions are provisional                                                                          | Derived from hero copy; require marketing approval before production                                                                                                                |
| A9  | Header and footer live in the root layout; current audience is derived from the URL                                  | They persist across audience switches (no flicker) and stay correct when rendered on the server                                                                                     |
| A10 | A tiny inline script adds `html.js` before first paint                                                               | Entrance animations and JS-only controls are scoped to `html.js`; without JS everything renders in its final state                                                                  |
| A11 | Glow and landscape backgrounds use the Figma SVG exports as `<img>`                                                  | Exact Figma look; the browser rasterises the blur once, so animating them is cheap                                                                                                  |
| A12 | Sections that clip decorative overflow use `overflow: clip` (fallback `hidden`)                                      | `hidden` makes the element a scroll container, which breaks `position: sticky` and CSS `view()` timelines                                                                           |
| A13 | Error boundaries: `app/error.tsx`, `app/global-error.tsx` and a branded `app/not-found.tsx`                          | A failing client island no longer blanks the page; 404s keep the header, footer and `main` landmark                                                                                 |
| A14 | JS-load failsafe in the inline `html.js` script                                                                      | If a Next.js chunk fails to load or the app has not hydrated within 8 s, the class is removed and the no-JS presentation takes over (all FAQ answers and tab panels, the Menu link) |
| A15 | Content-Security-Policy and Cross-Origin-Opener-Policy on built pages                                                | Same-origin only. Static pages need `'unsafe-inline'` scripts (inline RSC payload); nonces would force dynamic rendering. Not sent by `next dev`                                    |
| A16 | Node.js pinned to `22.x` in `engines`                                                                                | Vercel reads `engines`; `>=22.13.0` would have built on Node 24.x while CI and local use 22                                                                                         |
| A17 | `*.vercel.app` hosts are never indexable; a `SITE_ENV=production` build without an https production `SITE_URL` fails | A staging deployment cannot be indexed by mistake, and production cannot ship localhost canonicals                                                                                  |

### braces assessment

Verified on the installed tree (`npm ls braces --all`, `npm explain braces`):

- Single path: `eslint-config-next@16.4.2 → @next/eslint-plugin-next@16.4.2 → fast-glob@3.3.1 → micromatch@4.0.8 → braces@3.0.3`, installed as a **dev** dependency. `npm ls braces --omit=dev` is empty and `npm audit --omit=dev` reports 0 vulnerabilities, so nothing in the production build or runtime depends on it.
- The only use of `fast-glob` in `@next/eslint-plugin-next` is `utils/get-root-dirs.js`, called by the `no-html-link-for-pages` rule to expand `settings.next.rootDir` from the ESLint config. This project does not set `rootDir`, so the glob is never evaluated; even if it were, the pattern comes from our own committed config, never from user or network input. The vulnerability requires an attacker-controlled pattern.
- Next.js's runtime bundles `picomatch` (not `braces`) under `next/dist/compiled`; it is not affected by this advisory.
- No safer compatible version exists: `braces@3.0.3` is the latest release; `fast-glob@3.3.3` still depends on `micromatch@^4.0.8 → braces@^3.0.3`. npm's suggested fix is a downgrade to `eslint-config-next@14`, which is incompatible with Next.js 16. No override or forced install has been applied.
- Residual risk: low (local/CI lint only). Re-check whenever `eslint-config-next` is updated.

## Accessibility notes

- **Product stages** are illustrations with sample data. Each is a `<figure>` with a text description (`figcaption`); the decorative dashboard markup and simulated live feeds are hidden from screen readers so they are not read out number by number or announced as they change.
- **Turn chat and MCP assistant** are product demos. Each is a `<figure>`: the visual markup is hidden from screen readers (so typing text is never read out half-finished) and the caption carries the full sample conversation. The MCP prompt chips are real buttons (`aria-pressed`); pressing one places the prompt in the demo composer and a polite live region announces it. Nothing is submitted.
- **FAQ**: categories are tabs; each question is a `button` with `aria-expanded`/`aria-controls` and its answer a labelled `region`. Collapsed answers are hidden from assistive tech (`visibility: hidden` after the 300ms transition). Without JavaScript every category and answer is shown.
- **Final CTA muted line** over the CTA glow: worst case **3.93:1** at the glow's peak frame (large text ≥3:1), covered by `tests/e2e/contrast.spec.ts`.
- **Case carousel** is a labelled `region` (`aria-roledescription="carousel"`) of `group` slides ("1 of 3: Unicon365"); controls are real buttons, the current dot has `aria-current`. Off-screen slides stay in the reading order.
- **Before/after slider** is a `role="slider"` with value text ("60% before, 40% after"); the images are decorative and the case copy carries the result.
- **Step explorer**: steps are buttons with `aria-current="step"`; the swapping window is decorative (`aria-hidden`, inactive windows `inert`). Networks' timeline is a plain ordered list.
- **Capability tabs** follow the WAI-ARIA tabs pattern; the visuals are decorative and a visible "Sample data" note is read out. Muted text inside the raised step windows and tab cards uses `--color-text-muted-strong` (`#8B95C0`; Figma `#7A84B0` measures 4.2–4.3:1 on their 3–5% overlays). Other raised cards use `--color-text-muted-raised` (`#7F89B5`). Both are tokens in `tokens.css`.
- **"Affnook" label in the indigo chat bubble**: Figma's 70% white measures 4.0:1 on `#4F46DB`; raised to 82% white (≥4.5:1).
- **Muted H1 line** (`#7A84B0`, Figma `text/muted`) over the indigo glow: measured on rendered pixels at the glow's brightest frame, worst case **3.59:1** (390/1440/1920px, all three audiences). This passes WCAG 2.2 AA for large text (≥3:1; the H1 is 40–88px semibold) but would not pass the 4.5:1 normal-text level. Kept as designed; covered by `tests/e2e/contrast.spec.ts`.
- **Audit fixes (2026-10-21)**: the "See Affnook for" label over the hero glow uses `--color-text-muted-glow` (`#949DC6`, ≥4.5:1; Figma `#7A84B0` measured 3.8–4.0:1); inactive carousel dots and the selected FAQ category have a ≥3:1 indicator (WCAG 1.4.11); carousel arrows use `aria-disabled` at the ends so keyboard focus is not lost; `scroll-padding-top` keeps focused elements clear of the fixed header (WCAG 2.4.11); header, menu and footer links that open a new tab now say so to screen readers.
- **Scroll word highlight** (Problem and Turn headings, testimonial quote): words that are not yet lit use 50% white (4.99:1) instead of the prototype's 16% white (1.5:1), so dimmed text also meets WCAG AA (found by Lighthouse on staging, 2026-10-21).
